**Ex 02 shows advanced sorting design, Jacobsthal insertion logic, container comparison
I implemented Ford-Johnson merge-insert sort for two containers: vector and deque.  
Then I compared their time.
I explain step by step what I did and why.

1. Input parsing and validation  
First, I read all numbers from command line.  
I accept only positive integers.  
I reject zero, negative numbers, overflow, mixed strings like 12abc, and wrong formats.  
Why: sorting is useless if input is not reliable, so validation is first defense.

2. Keep original input  
I keep original numbers for printing Before line.  
Why: subject asks to show data before and after sorting.

3. Split into pairs  
I group numbers by two.  
For each pair, I put smaller value first and bigger value second.  
If count is odd, one value stays unpaired.  
Why: this is base idea of Ford-Johnson.  
By putting smaller first, I know relation inside each pair.

4. Sort pairs by second value  
Then I sort all pairs using second number of each pair.  
I used recursive merge sort for this part.  Why:
1. It follows Ford-Johnson merge-insert idea from classical description.

5. Build main chain  
After pair sorting, I take all second values and make main sorted chain.  
Why: second values are already ordered after previous step, so this is a strong base chain.

6. Prepare insertion order with Jacobsthal sequence  
Now I must insert first values of pairs into main chain.  
I do not insert left to right. I generate Jacobsthal-based order, 
for example pattern like 1, 3, 2, 5, 4, then next block in reverse.  
Why: this order reduces number of comparisons in binary insertion.  
Main idea: better order means fewer compare operations overall.

7. Insert first values with binary search  
For each index from Jacobsthal order, I take first value from that pair and insert into main chain with lower_bound.  
Why: lower_bound is binary search insertion point, so insertion decision is efficient.

8. Insert unpaired value  
If input size was odd, one element was outside pairs.  
I insert it at correct position with lower_bound too.  


9. Build two versions: vector and deque  
I run same algorithm for vector and for deque.  
Subject asks to compare containers, not just one implementation result.

10. I measure processing time in microseconds for vector and deque separately and print. 
1. Before
2. After
3. Time for vector
4. Time for deque  

11. Error handling and robustness (Stärke прочность)
Program returns error code on invalid input.  
It prints clear error messages.  
No raw pointers and no manual memory management, no leaks.

12. Testing strategy  
I tested:
1. Basic small lists
2. Duplicates
3. Invalid arguments
4. Random bigger lists
5. 3000 numbers from subject style
6. Leak checks and return codes  

Complexity note
This implementation is a hybrid approach: merge phase plus insertion phase.
Merge alone is O(n log n).
Insertion alone is O(n^2).
In this Ford-Johnson implementation, comparison behavior is close to O(n log n).
Real runtime can approach O(n^2) because middle insertions in containers require element shifts.

ex02 (PmergeMe, main part)

Q: What is the main idea of ex02?
A: Implement Ford-Johnson merge-insert sort and compare vector vs deque timing.

Q: High-level steps of your algorithm?
A: Parse input, make pairs, normalize pairs, sort pairs by second value, build main chain, insert first values in Jacobsthal order, insert leftover value.

Q: Why split into pairs?
A: Pairing gives structure: each pair has small and big element, useful for controlled insertion.

Q: Why sort pairs by second value?
A: Then second values form an ordered backbone (main chain).

Q: What is main chain?
A: Sorted list of all pair second elements, used as base sorted sequence.

Q: What is pend chain (or pending values)?
A: The first elements of pairs, which are inserted later into main chain.

Q: Why Jacobsthal order, not left-to-right?
A: It reduces number of comparisons during binary insertions.

Q: What are Jacobsthal numbers?
A: Sequence with recurrence 

J(n)=J(n−1)+2J(n−2), used to define insertion groups.

Q: Why insert with lower_bound?
A: It uses binary search, so position lookup is efficient in sorted chain.

Q: What if input count is odd?
A: One leftover value is inserted at the end with lower_bound.

Q: Why implement for both vector and deque?
A: Subject asks to compare two STL containers on same algorithm and same input.

Q: Are results always identical for vector and deque?
A: Yes, sorted output must be identical. Only timing can differ.

Q: Which is usually faster in your tests?
A: Usually vector is slightly faster because of contiguous memory/cache behavior.

Q: Why did you use recursive merge sort for pair sorting?
A: It matches the merge-insert spirit and gives clean, deterministic sorting of pairs.

Q: Complexity in simple words?
A: Better than naive insertion strategy in comparisons; uses structured insertion order plus binary search.

Q: What do you print in output?
A: Before sequence, after sequence, time for vector, time for deque (microseconds).

Q: How did you test correctness?
